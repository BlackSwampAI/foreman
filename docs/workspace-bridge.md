A console session authenticated with the documented initial local credentials; values were not saved or exposed. With no backend enabled, harness discovery returned an empty list and model entries were unavailable. The host has no active Gemini CLI account or cached OAuth credential, API key, Vertex project, or ADC configuration, so the authorized one-task smoke condition was not met and no provider task was attempted. A previous machine check found no HarnessRouter/Hindsight containers or listeners on 8787, 3000, 8000, or 8888; the probe used only 3137. The official GitHub source tag `v0.23.7` (commit `809392d`) and Docker Hub image tag are distinct version streams; equivalence between them was not established. ## What the available contracts expose

| Surface | Published behavior | Workspace change capture |
| --- | --- | --- |
| Portable UHP | Discover configured harnesses and per-harness models; submit Responses-compatible tasks; stream progress; retrieve responses, sessions, and session files; upload inputs; cancel tasks. | UHP's file surface returns every **artifact** of a session. It does not define checkout selection, a base commit, a complete workspace tree/snapshot, a changed-path manifest, or a diff. Treat returned artifacts as outputs, not as proof of all workspace edits. |
| HarnessRouter API | The installed CE runtime's `/v1/uhp` reports the capabilities listed above. The tagged `v0.23.7` source provides `GET /v1/sessions/{id}/files`, `?changed=true`, an archive route, and path-based read/write routes. | **Tagged-source inspection only; pinned-runtime task behavior is unverified.** In that source, listing filters out every dot path (including `AGENTS.md` and `.gitignore`), the archive includes regular files only, `changed=true` describes files created/modified on the most recent turn, and neither route reports deletions or a pinned base commit. The source has no complete snapshot/diff endpoint. No task was submitted to the pinned image because it had no configured harness and no cached provider auth was present. Direct access to `/data/workspaces` is not a supported bridge contract. |
| Proposed UHP snapshot extension | No such endpoint or capability was found in the published UHP API map reviewed for this work. | A portable extension would need to be explicitly advertised, versioned, and contract tested. Suggested contract is a session-scoped base snapshot plus a post-run complete manifest. Every entry carries relative path, kind, mode, size, and content or a content-addressed download handle; symlinks carry their link target. The base reference is an immutable commit/tree ID. It must state how inaccessible or oversized entries are reported and fail closed if the snapshot is incomplete. |
| Complete snapshots diffed locally | `snapshotGitCommit` in `src/git-workspace.ts` reads all blobs from an exact full commit SHA, including dotfiles, instruction files, binary data, executable bits, and symlink targets; `verifyGitSnapshotScope` compares a supplied complete result manifest to that base and rejects out-of-scope paths, unsafe/malformed entries, excess size/count, and unsupported submodules. | Deterministic local Git fixtures cover additions, modifications, deletions, identical-content renames, binary data, executable mode changes, symlinks, dotfiles, and `AGENTS.md`; a separate test checks out-of-scope changes (including rename source), manifest bounds, full SHA requirement, and submodule rejection. This verifies Foreman's local base/scope comparison only. It does not verify that HarnessRouter can export a complete post-run workspace snapshot or preserve all filesystem entries. |

## Contract sources and next verification

- UHP [2026-09-12 Harnesses](https://unifiedharnessprotocol.org/spec/2026-09-12/harnesses) and [2026-08-11 Harnesses](https://unifiedharnessprotocol.org/spec/2026-08-11/harnesses) define scoped harness and model discovery. The adapter negotiates 2026-09-12 when present, otherwise 2026-08-11; it refuses servers advertising neither.
- UHP [2026-09-12 Tasks](https://unifiedharnessprotocol.org/spec/2026-09-12/tasks), [Streaming](https://unifiedharnessprotocol.org/spec/2026-09-12/streaming), and [Files](https://unifiedharnessprotocol.org/spec/2026-09-12/files) define task IDs/session IDs, terminal states, idempotency, event streams, uploads, and session artifact list/archive. The [2026-08-11 Tasks](https://unifiedharnessprotocol.org/spec/2026-08-11/tasks) and [Streaming](https://unifiedharnessprotocol.org/spec/2026-08-11/streaming) specs use the fields and event ordering required by this adapter version. Files describes artifacts, not a full workspace tree.
- The [HarnessRouter Community Edition repository](https://github.com/HarnessRouter/harnessrouter) documents its `/api/harness/v1` Responses-compatible routes, session continuation, streaming, file upload/output retrieval and cancellation. The [workspace docs](https://www.harnessrouter.ai/docs/workspace) state that API keys, configured agents, sessions and returned files are scoped to a workspace. Neither source inspected here specifies a full workspace snapshot API.
- The tagged [HarnessRouter file listing route](https://github.com/HarnessRouter/harnessrouter/blob/v0.23.7/gateway/app.py#L9149) reads the checkpoint archive and returns user-visible regular files. Its [archive route](https://github.com/HarnessRouter/harnessrouter/blob/v0.23.7/gateway/app.py#L9213) skips non-regular entries and preserves regular-file mode bits in ZIP metadata. The [visibility filter](https://github.com/HarnessRouter/harnessrouter/blob/v0.23.7/gateway/app.py#L8867) excludes all dot paths and explicitly excludes `AGENTS.md`, `CLAUDE.md`, and `.gitignore`.
- The official [HarnessRouter Docker Hub tags](https://hub.docker.com/r/harnessrouter/harnessrouter/tags) list the CE image tag used above. The GitHub [v0.23.7 source release](https://github.com/HarnessRouter/harnessrouter/releases/tag/v0.23.7) resolves to commit `809392d`; it is not the same tag as the image. In the pinned image, the observed implementation version is `0.3.0` and the observed UHP version is `2026-08-11`.
- [Hindsight bank creation](https://docs.hindsight.vectorize.io/api-reference/create-or-update-bank/), [recall](https://docs.hindsight.vectorize.io/recall/), and [retain](https://docs.hindsight.vectorize.io/retain/) provide the project-bank provisioning and memory operations used by the adapter.

Remaining proof: configure an actual HarnessRouter backend and run deterministic, no-provider tasks in a disposable fixture workspace to check whether task execution plus the supported artifact API can export a complete post-run state. Until that test is possible, the file-case assertions about HarnessRouter are explicitly limited to tagged source `v0.23.7`; runtime equivalence is unproven. Foreman's local Git verifier cannot fill that export gap by itself: it needs a complete result manifest from the actual task workspace.

## Proposed smallest sound bridge

For a router without a full snapshot contract, use an explicit runtime-side bridge that emits a complete, bounded manifest from the task's actual workspace before and after execution. Pin the start snapshot to a base commit; keep binary bytes and filesystem modes; represent symlinks without dereferencing them; include ignored/untracked paths, dotfiles, and instruction files. Return an explicit incomplete/error result when any path could not be read. Store and compare the returned snapshot in Foreman. Keep the manifest/diff contract behind a capability or adapter so portable UHP servers that do not implement it report “workspace comparison unavailable” instead of implying a clean diff.

This is a recommendation from the contract gap, not a verified HarnessRouter feature. Do not implement it by scraping the CE container's internal workspace paths: that would couple Foreman to one deployment's private layout and bypass the API's authorization boundary.
