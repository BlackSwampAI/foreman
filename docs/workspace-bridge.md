## Implemented local bridge shape

The local server implements the workspace protocol as an external investigation service. Its workspace operation is scoped to the server-configured source repository and pinned commit. The complete snapshot carries exact file bytes, executable mode, and symlink target. Unreadable, special, and oversized paths become explicit errors. Foreman persists the bridge response IDs, actual model and measured usage when returned, exact pinned base, completeness, verified changes/scope, and computed diff. The bridge completeness value is only a transport claim; Foreman validates the entries and derives Git changes and scope itself.

The controller materializes the verified diff in a disposable workspace from the pinned base. It executes configured validation commands with time bounds and captures exit status and output. **Every command in the non-empty configured list must pass**; commands omitted from the list are not run or inferred, so a partial list is only evidence for those configured checks. Configure all four settings together: `FOREMAN_WORKSPACE_SOURCE_REPO`, `FOREMAN_WORKSPACE_BRIDGE_URL`, `FOREMAN_WORKSPACE_ALLOWED_SCOPE`, and non-empty `FOREMAN_VALIDATION_COMMANDS`. Any partial configuration makes service startup fail. Those observations, rather than Worker or Reviewer prose, determine whether the validation policy passed. The Reviewer receives the exact diff and controller-observed checks; Foreman records its recommendation, harness/model, response ID, and rationale as separate evidence. Earlier recommendations remain in history when a non-recommending result is explicitly retried. The UI exposes latest and prior recommendations with provenance, the diff, checks, and pending approval state. A human must explicitly approve or reject using the UI or `POST /api/runs/{runId}/approve` with `{ "approved": true|false }`; a decision requires verified snapshot/scope, passing configured validation, and a recorded recommendation. Approval is an immutable human decision, not a Git result. `approval.evidenceCommit` identifies the pinned input base only. After approval, a separate explicit `POST /api/runs/{runId}/promotion` requests Git promotion, defaulting to local branch `foreman/results/{runId}` unless `destinationBranch` is supplied. The controller rechecks stored evidence and bindings, materializes exact bytes, modes, deletions, and symlinks in an isolated worktree, commits on the pinned base, and independently verifies the complete result tree before setting promotion status to `applied`. Promotion status and result commit/tree IDs are recorded separately. Retries are idempotent; base drift, changed evidence, missing objects, and conflicting destination refs fail closed. The recommendation's verdict is advisory: a Reviewer rejection neither automatically rejects nor accepts the result, and the operator makes the final decision after inspecting the evidence. Foreman does not apply Reviewer-proposed changes.

## Operator sequence for a future live run

1. Configure all four settings together: `FOREMAN_WORKSPACE_SOURCE_REPO`, `FOREMAN_WORKSPACE_BRIDGE_URL`, `FOREMAN_WORKSPACE_ALLOWED_SCOPE`, and a non-empty `FOREMAN_VALIDATION_COMMANDS` JSON list. Partial configuration fails service startup. Every configured command must pass; commands omitted from the list are not inferred or run.
2. Create the project, task, and run, select the Worker/Reviewer harnesses and models, then pin and seed the run with `POST /api/runs/{runId}/workspace` and `{ "baseCommit": "<full Git commit SHA>" }`.
3. Submit the Worker with `POST /api/runs/{runId}/assignments` and `{ "roleId": "worker", "prompt": "..." }`. After its assignment succeeds, call `POST /api/runs/{runId}/worker-evidence` with `{ "assignmentId": "<Worker assignment ID>" }`. Foreman retrieves the Worker response and bridge snapshot, verifies the exact pinned base/scope, materializes the verified output, and runs the configured checks.
4. After controller validation passes, submit the Reviewer through `POST /api/runs/{runId}/reviewer`. The bridge opens a fresh review context with no `workspace_id` or checkout; Foreman sends only the exact verified diff and controller-observed validation evidence. Claude has an empty tool allowlist. Codex uses `--sandbox read-only`, which may retain read-only shell tools; this Codex boundary was fixture-tested only. The recorded live Claude response is in [actual-reviewer-smoke.json](../investigations/local-cli-uhp/evidence/actual-reviewer-smoke.json); the separate checked-in integration fixture labels its Reviewer `simulated_fixture` and is not live model evidence. Inspect rationale, requested and actual model, response/session IDs, measured usage, provenance, and prior recommendation history in the UI.
5. Make the human decision in the UI or with `POST /api/runs/{runId}/approve` and `{ "approved": true|false, "rationale": "..." }`. Foreman rejects approval unless snapshot/scope verification, configured validation, and a Reviewer recommendation are present. The decision records `evidenceCommit` as the pinned input base; it does not create a result commit.
6. After an approved decision, explicitly request Git promotion in the UI or with `POST /api/runs/{runId}/promotion` and optional `{ "destinationBranch": "..." }`. Inspect separate promotion status and result commit/tree. A retry reuses the operation identity and refuses changed evidence, base drift, missing Git objects, and a conflicting destination branch. A human rejection is terminal for that run. To retry failed validation, use `POST /api/runs/{runId}/validation/retry`. To authorize a Reviewer retry after a non-recommending result, use `POST /api/runs/{runId}/reviewer/retry`, then submit a new Reviewer request. Previous recommendation records remain inspectable. A new Worker attempt requires a new run and workspace seeded from its pinned base. The previously approved live smoke run has not been promoted. Its legacy decision lacks an evidence digest and cannot pass the current promotion binding check; a new bound decision or explicit migration would be required, and neither is performed here.

The checked-in Claude Worker smoke response can be loaded through Foreman's recorded evidence import path. Foreman verifies its exact response/snapshot bytes against the full pinned Git base and recomputes scope and diff before storing it as `recorded_live_import`; importing the evidence does not invoke the Worker. The integration test separately replays the sanitized evidence as `recorded_replay` and uses its own deterministic simulated Reviewer. Neither fixture is a live model run, and neither the smoke record nor fixture is approved automatically.

The existing `snapshotGitCommit` and `verifyGitSnapshotScope` functions are core Git utilities; the network workspace protocol and CLI server remain outside Foreman's core. Portable UHP artifact endpoints continue to represent session outputs, not complete Git snapshots.
