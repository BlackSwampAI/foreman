It does not change portable UHP semantics or Foreman's core adapter contract. See the [bridge run and endpoint contract](../investigations/local-cli-uhp/README.md#bridge-specific-git-workspace-extension).

## Claude and Codex alternative auth check

The operator requested Claude and Codex after Gemini authentication proved unavailable. On the host, Claude Code `2.1.280` reports an existing Claude.ai login and Codex CLI `0.156.0` reports an existing ChatGPT login. This confirms local CLI authentication status only. The pinned HarnessRouter container was installed with `HR_BACKENDS=none`, has no configured Claude/Codex provider integration, and does not inherit host CLI login state. The pinned image's gateway source rejects a response task before dispatch when the selected backend has neither an integration nor a connection policy. Its runner sets `CLAUDE_CONFIG_DIR` and `CODEX_HOME` under each session workspace and configures provider credentials from the selected integration. The documented CE setup likewise calls for a provider API key distinct from the HarnessRouter API key. `ANTHROPIC_API_KEY` and `OPENAI_API_KEY` were unset in this environment; no provider key was acquired or copied from CLI account state. Recreating the probe with `HR_BACKENDS=claude,codex` would install those backends but would not resolve the missing provider connection. No task was submitted to the pinned HarnessRouter probe. The [subscription CLI investigation](subscription-cli-uhp.md) records a successful, separately authorized Claude Code task through an external UHP bridge, with actual IDs and measured usage; it does not close the HarnessRouter authentication or workspace export gaps.

## File-case evidence matrix

“No guarantee” means the API does not promise that case in a complete workspace snapshot. It is not a claim that HarnessRouter cannot perform the change internally.

| Case | Portable UHP artifacts | HarnessRouter tagged source v0.23.7 (runtime untested) | Foreman Git snapshot fixture |
| --- | --- | --- | --- |
| Added file | No complete-tree guarantee | Tagged source `v0.23.7` returns user-visible regular files after checkpoint; hidden paths are excluded. Pinned runtime untested. | Git snapshot fixtures cover it |
| Modified file | No before/after content contract | Tagged source `v0.23.7` can return current visible bytes; no base comparison. Pinned runtime untested. | Git snapshot fixtures cover it |
| Deleted file | No deletion manifest | Tagged source `v0.23.7` has no tombstone/diff; `changed=true` is additions and modifications only. Pinned runtime untested. | Git snapshot fixtures cover it |
| Renamed file | No old-path/new-path contract | No rename contract in inspected `v0.23.7` source. Pinned runtime untested. | Git snapshot fixture detects identical content rename |
| Binary file | Artifact download can carry file bytes; no workspace-wide binary changeset | Tagged source `v0.23.7` archives visible regular bytes; no complete changed binary set. Pinned runtime untested. | Git snapshot fixtures cover exact bytes |
| Executable bit | No complete mode manifest | Tagged source `v0.23.7` archive writes regular-file mode bits, but has no complete manifest. Pinned runtime untested. | Git snapshot fixtures cover mode changes |
| Symlink | No symlink entry contract for a complete tree | Tagged source `v0.23.7` list/archive skip non-regular tar members, including symlinks. Pinned runtime untested. | Git snapshot fixtures cover symlink targets |
| Dotfile | No complete-tree visibility promise | Tagged source `v0.23.7` filters paths starting with `.` from list/archive. Pinned runtime untested. | Git snapshot fixtures cover dotfiles |
| `AGENTS.md` / instruction file | May be an artifact only if returned; no guarantee every changed instruction file is enumerated | Tagged source `v0.23.7` explicitly hides `AGENTS.md`, `CLAUDE.md`, and `.gitignore` from list/archive. Pinned runtime untested. | Git snapshot fixtures cover `AGENTS.md` |

The external bridge test file passed **11/11** deterministic tests. Together
with Foreman's Git fixture, it exercises all nine file cases above: additions,
regular edits, deletions, identical-content rename detection, binary bytes,
executable mode, symlink target, dotfiles, and `AGENTS.md`. The seed fixture
also includes a `.gitattributes export-ignore` file to prove the bridge seeds
from the full Git tree rather than an archive that omits ignored paths. Tests
reject incomplete and oversized snapshots. These are local extension tests;
they do not establish equivalent behavior in the pinned HarnessRouter runtime.

## Implemented local bridge shape

The local server implements this shape as an external investigation service. Its workspace operation is scoped to the server-configured source repository and pinned commit. The complete snapshot carries exact file bytes, executable mode, and symlink target. Unreadable, special, and oversized paths become explicit errors. The verifier validates each entry's byte count and hash, then reads the same full commit locally and calls `verifyGitSnapshotScope` with the allowed paths. Its evidence includes a review diff and exact hashes/bytes. The bridge's completeness flag is recorded as a transport claim; Foreman derives Git changes and scope itself and does not turn that into task acceptance.

The existing `snapshotGitCommit` and `verifyGitSnapshotScope` functions are core Git utilities; the network workspace protocol and CLI server remain outside Foreman's core. Portable UHP artifact endpoints continue to represent session outputs, not complete Git snapshots.
