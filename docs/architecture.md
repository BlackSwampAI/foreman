# Foundation architecture

Foreman runs one local Node service. A durable JSON state file holds projects, tasks, runs, role configuration, assignments, guidance, validation, review, approval, and append-only event records. Each mutation is serialized and atomically renamed into place. The React UI reads that persisted state and receives events over SSE (push-on-mutation, not polling). UHP and Hindsight are adapters at the service boundary; neither owns Foreman's project identity or canonical Git truth. `/api/state` omits binary file contents and trims high-volume progress events; the full evidence payload is served on demand via `/api/runs/:id/evidence`.

## Control flow

1. The operator creates a persistent project, task, and run, then speaks to the Planner. The Planner is the only primary chat surface. For Claude Code or Codex harnesses, the Planner receives a read-only snapshot of the repository at HEAD; for Antigravity CLI or when the snapshot cannot be seeded, it receives a deterministic digest (file tree, package.json summary, README excerpt, rarity-weighted keyword hits). The digest is sized from the prompt budget that remains after the mandatory parts (capped at 12 KB, tree truncated to fit, omitted with a recorded reason below ~1.5 KB), so Foreman-supplied context never pushes a turn over the 15,000-byte prompt limit.
2. The Planner and Orchestrator use separate UHP session chains. Foreman records each response and session ID so a session may continue or rotate without replacing the project. A rotation changes the UHP conversation identity; project memory and Git promotion state remain attached to the project.
3. The Orchestrator proposes bounded Worker assignments. It must return a strict JSON object `{"workerTask":"...","targetFiles":["relative/path",...]}`. Scope is checked against `targetFiles` before dispatch; the post-run snapshot diff remains the authority for what changed. Foreman validates the requested harness/model against live discovery, persists the submission intent and idempotency key, then sends UHP work. Workers are inspectable but are not direct operator chat targets.
4. New operator guidance is assigned a monotonic sequence. While a Worker is active, it waits in the durable queue. At a defined checkpoint, the Orchestrator acknowledges whether it applied the guidance, needs to replan, or is waiting. Invalidated Worker work is cancelled and revised explicitly.
5. A Reviewer independently examines proposed changes and evidence. Foreman must independently verify the exact Git result and configured validation before a human approval can accept changes. A Reviewer response or human approval alone cannot mutate canonical Git state. Approval and Git promotion are distinct persisted states.
6. Role configuration follows three scopes: Global → Project → Run. The more specific scope overrides the less specific one. Project and run overrides store only explicitly set choices; unset roles inherit from above. Discovery does not overwrite a saved choice.

## Authority and failure behavior

Agent prose is evidence or a proposal, not a state transition by itself. Git commits, exact workspace snapshots, and controller-observed checks are authoritative for code acceptance. Hindsight recall is bounded and advisory. If Hindsight is unavailable, memory status degrades visibly while ordinary run state and validation remain available. Usage is represented as measured only when reported by UHP; missing token, cost, or quota fields remain unavailable.

The external host CLI bridge remains outside Foreman core. Foreman persists its Worker response provenance and complete snapshot, verifies the snapshot and scope against the pinned base, computes an exact diff (3-line context hunks, 48 KB limit), then runs configured validation commands in a disposable workspace derived from that base. Recorded live Worker evidence can be imported and reverified locally without starting another Worker task; this receives its own `recorded_live_import` provenance distinct from deterministic `recorded_replay`. The Reviewer receives the diff and controller-observed checks in a fresh context without the Worker checkout. Claude Code runs with only Read, Edit, and Write tools allowed; Codex runs with `--sandbox read-only`; Antigravity uses `commandExecutionPolicy: "off"`. Foreman records recommendations independently; they cannot change the verified diff or mark it accepted, and Foreman does not apply Reviewer changes. Human approval is a separate decision transition, gated on verified snapshot/scope and configured validation policy; Git promotion remains explicit and later.

When the Orchestrator returns an empty or soft-denied response (e.g. AGY invoking disallowed tools), Foreman classifies it with a plain reason, stores it on the assignment, and allows one bounded automatic retry with a clarified prompt. A per-check results panel in the UI shows passing and failing commands with failing test extraction. The evidence diff is limited to 48 KB; tasks producing larger diffs must be split.


## Approval and Git promotion

Human approval records an immutable decision bound to the evidence digest and pinned input base. The digest is the one the operator reviewed: `GET /api/runs/:id/decision` returns it with the Worker response, validation, and Reviewer recommendation IDs it covers (only at a decision checkpoint), and the approve/reject request must carry it as `evidenceDigest`. `approveRun` recomputes the digest inside the same store mutation and refuses a missing or malformed value (400) or a stale one (409), so an approval or rejection never applies to evidence the operator did not see. Its `evidenceCommit` names the pinned base; it is not the result commit. Promotion is a separate explicit operation. Before creating a result commit, the controller rechecks the stored snapshot bytes and modes, allowed scope, pinned base, validation record, and Reviewer binding. It builds the tree in an isolated worktree, commits with the pinned base as parent, then compares the complete result tree to the approved snapshot. Only that verified result commit and tree are reported as applied. A failed or interrupted attempt remains distinct from the human decision and can be retried idempotently; conflicting branch state is rejected.
