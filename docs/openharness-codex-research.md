# OpenHarness Codex design notes

Inspected [`autonomous-ai/openharness` at `b5edd10a97fee4b764f0b0cb020c8634782a5ebd`](https://github.com/autonomous-ai/openharness/tree/b5edd10a97fee4b764f0b0cb020c8634782a5ebd) on 2026-09-23. This repository is the terminal, daemon, and desktop project that launches the installed Codex CLI. The similarly named [`HKUDS/OpenHarness`](https://github.com/HKUDS/OpenHarness) has a Codex subscription client that calls an HTTP endpoint with a token; it is a different implementation and does not establish CLI workspace behavior.

| Concern | Pinned implementation | Implication for Foreman |
| --- | --- | --- |
| Codex invocation | [`engineLaunch.ts`](https://github.com/autonomous-ai/openharness/blob/b5edd10a97fee4b764f0b0cb020c8634782a5ebd/cli/src/lib/engineLaunch.ts) builds native `codex` argv, including `codex resume <id>` and `codex fork <id>`; [`tmuxBackend.ts`](https://github.com/autonomous-ai/openharness/blob/b5edd10a97fee4b764f0b0cb020c8634782a5ebd/cli/src/lib/tmuxBackend.ts) starts it in a tmux session with a chosen cwd and session environment. It is an interactive terminal integration, not a Responses or UHP adapter. | Reuse the principle of invoking the user's installed CLI, while keeping Foreman's current bounded UHP transport. |
| Host login | A normal launch inherits the host CLI environment. An optional Codex profile supplies `CODEX_HOME`; [`codexProfiles.ts`](https://github.com/autonomous-ai/openharness/blob/b5edd10a97fee4b764f0b0cb020c8634782a5ebd/cli/src/lib/codexProfiles.ts) discovers host profile directories, and [`ownLoginProvider.ts`](https://github.com/autonomous-ai/openharness/blob/b5edd10a97fee4b764f0b0cb020c8634782a5ebd/cli/src/engines/codex/ownLoginProvider.ts) restores the configured provider on return from a separate Grid path. | An existing host login can be used without an API key. Foreman still needs its stricter read-only auth mount and environment allowlist; OpenHarness does not prove that boundary. |
| Workspace and isolation | [`git_worktree.dart`](https://github.com/autonomous-ai/openharness/blob/b5edd10a97fee4b764f0b0cb020c8634782a5ebd/desktop/lib/core/git_worktree.dart) prepares a Git worktree on a branch and [`project_folder.dart`](https://github.com/autonomous-ai/openharness/blob/b5edd10a97fee4b764f0b0cb020c8634782a5ebd/desktop/lib/core/project_folder.dart) hands its path to launch. Codex's own permission flags are mapped in `engineLaunch.ts`. | A worktree keeps edits separate, but is not a filesystem sandbox or complete diff proof. Foreman retains bubblewrap and its independent pinned-snapshot, scope, and validation checks. |
| Sessions | Native CLI resume/fork argv and [`rollout.ts`](https://github.com/autonomous-ai/openharness/blob/b5edd10a97fee4b764f0b0cb020c8634782a5ebd/cli/src/engines/codex/rollout.ts) track Codex's own sessions and JSONL rollouts. | Keep CLI session IDs distinct from UHP response IDs; do not infer continuation from an ID alone. |
| Usage | [`agentTokenUsage.ts`](https://github.com/autonomous-ai/openharness/blob/b5edd10a97fee4b764f0b0cb020c8634782a5ebd/cli/src/lib/agentTokenUsage.ts) reads `token_count` rollout events and deduplicates cumulative totals. The [desktop Codex ledger](https://github.com/autonomous-ai/openharness/blob/b5edd10a97fee4b764f0b0cb020c8634782a5ebd/desktop/lib/usage/ledger/codex_ledger_scanner.dart) explains that `last_token_usage` is incremental, `total_token_usage` is cumulative, input includes cache reads, and output includes reasoning. | Record only observed CLI fields and their source. Do not add cumulative snapshots together or equate different CLIs' token totals with cost or underlying request count. |

The research supports retaining Foreman's existing bridge and controller. It does not justify a router replacement or a claim that tmux and worktree separation satisfy Foreman's Worker isolation policy.
